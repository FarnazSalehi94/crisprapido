# Feasibility of PAM-aware indexed search

Date: 2026-11-04. Scope: investigation only, on `dev/mismatch5-bulge2-defaults`. No redesign or new experiment was run. The current defaults remain `-m 5 -b 1 -z 2 -f 0.75`.

## Recommendation

Prototype a **PAM-anchored, constrained FM-index search using Columba's index primitives**, in an isolated research checkout. Start with a simple complete state-space traversal and the independent small-panel oracle, before optimizing with search schemes. Enumerate eligible alignments at each anchor and reproduce the current representative policy; retain WFA2 as a comparison oracle during development. Do not use CFD to prune in the initial prototype. This direction addresses discovery and verification together, but its completeness and performance are unproven. A safer nearer-term alternative is the previously investigated interval-level PAM precheck, which reduces verification work but does not eliminate Columba's candidate explosion.

The saved CHM13 ELMOD2 e=7 run had 17,653,389 mapped SAM rows, not 17.65 million independently validated sites. The prior analysis found 96.17% of raw spans lacked an immediately adjacent strict PAM, but deleting them lost 21 of 204 oracle anchors: WFA2 expands a candidate into overlapping alternative spans. The conservative overlapping-span screen and an interval precheck have different guarantees and costs. See [candidate investigation](candidate_efficiency_61a4cfc_2026-11-02_v1/REPORT.md). An integrated search must find the *actual PAM-anchored alignment*, not filter the raw Columba CIGAR's PAM.

## BWA-ALN

The [2009 BWA paper](https://doi.org/10.1093/bioinformatics/btp324) describes an FM-index backward search: a suffix-array interval represents all reference suffixes matching the current string. An extension by base `c` uses the BWT cumulative counts and rank/Occ to update that interval; an empty interval ends the branch. Repeated reference substrings share a search path; locate later resolves interval members to genomic positions. For inexact search, backtracking branches over matching/substituting a base, consuming a query base without a reference base, or consuming a reference base without a query base. A state carries remaining query position, SA interval and edit/gap information. Search can have exponential growth in the error budget.

The paper's lower-bound array D estimates the minimum differences needed by the remaining query using exact-search failures on the reverse index; a state is impossible when its remaining budget is below that lower bound. In current [bwtaln.c](https://github.com/lh3/bwa/blob/master/bwtaln.c), `bwt_cal_width` constructs widths and `bid` bounds, and `bwa_cal_sa_reg_gap` invokes [bwtgap.c](https://github.com/lh3/bwa/blob/master/bwtgap.c)'s `bwt_match_gap`. `gap_push`/`gap_pop` organize states by mismatch/gap-open/gap-extension penalty, with LIFO behavior within a score. `STATE_M`, `STATE_I`, `STATE_D` distinguish gap opening and extension; empty intervals, budgets, lower bounds, seed restrictions and exact completion prune or shortcut branches. The implementation also uses best-score/top-two stopping, end-gap restrictions, repeat-dependent deletion extension and a maximum stack size. `-N` disables some iterative stopping, not every limit or downstream output restriction. Standard BWA-ALN is therefore **not a guarantee of every eligible CRISPR site or every alignment**, even with `-N`; the [Columba paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC12724072/) reports missed optimal alignments/locations in its benchmark. A complete custom algorithm could reuse admissible lower bounds, explicit gap state, exact completion and shared SA intervals, but must remove or prove every heuristic and enumerate locations and traces.

BWA-ALN is the short-read, BWT backtracking algorithm in the 2009 paper. BWA-MEM is a later seed-and-extend mapper using maximal exact matches and local alignment; it has different heuristics and is not the algorithm assessed here. Neither standard command is a drop-in exhaustive PAM-anchored off-target finder.

## Columba internals and change surface

The [Columba paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC12724072/) and its [search-schemes predecessor](https://pmc.ncbi.nlm.nih.gov/articles/PMC8246400/) describe paired forward/reverse index intervals for the same substring. Rank operations update both intervals when extending either end, allowing a connected sequence of pattern parts to be searched in either direction. A scheme specifies part order and cumulative lower/upper edit bounds. A branch fails if its interval is empty or its DP/edit state cannot meet those bounds. A scheme is lossless only for the error distributions and metric it actually covers. The paper's all-optimal read alignment guarantee is not a guarantee of all eligible, potentially non-minimum alignments at each PAM anchor.

Source reviewed is upstream `main` as retrieved on 2026-11-04; the externally supplied runtime used by CRISPRapido is not version-pinned in this repository, so its exact source/build identity must be established before implementation or performance claims. Concrete upstream modification points for a constrained prototype are:

Columba's edit search uses edit-distance DP and can generate CIGARs, but its scalar distance and post-processing do not encode CRISPR's separate mismatch, gap-group and gap-length limits. In principle an expanded search state or multi-label DP can encode them and retain traceback without WFA2. It must retain nondominated alternatives, not just one minimum-edit path: the minimum-edit alignment may violate a separate limit when another alignment at the same anchor passes. Columba can also switch from index traversal to its own in-text verification (`recApproxMatchEditEntry`); removing WFA2 does not necessarily mean no sequence-level verification. The feasibility of a completely in-index implementation and performance of expanded states require measurement. Upstream source is AGPL-3.0-or-later; assess distribution and maintenance implications before adopting a fork.

## Guide plus PAM

For strict requested `GG`, model the oriented pattern as `guide + [ACGT]GG`. PAM transitions consume exactly one reference base per pattern position, require the stated base set, cost zero guide edits, and permit no gap in or across the guide/PAM boundary. Search the reverse complement as well (genomic `CC[ACGT] + reverse-complement(guide)`) or prove the index's strand conversion equivalent. A PAM N is a wildcard over **resolved reference A/C/G/T only**, not an ambiguous reference N. Case normalization and contig boundaries matter. For zero-based half-open protospacer `[s,e)`, plus PAM is `[e,e+3)`, minus PAM is `[s-3,s)`; the reported anchor is `e` on plus, `s` on minus. Strip PAM operations before emitting the guide CIGAR and preserve target span, strand and guide orientation. Do not let an indel absorb or shift a PAM base; enumerate each distinct anchor explicitly, including terminal guide gaps according to current eligibility/normalization.

Existing `extract_adjacent_pam` requires a complete three-base A/C/G/T PAM, reverse complements on minus, and returns the final two bases in guide orientation. `--pam` accepts any two resolved bases, not just GG. Strict output groups per query/contig/strand/PAM-adjacent boundary and selects a deterministic representative. `--allow-noncanonical-pam` retains noncanonical **or unavailable** PAMs, while `--no-filter` also bypasses sequence/PAM eligibility; therefore hard strict-NGG indexing alone cannot preserve those modes. Keep a separate compatible path or explicitly implement all their semantics, including incomplete/ambiguous edge PAMs; do not silently narrow results. Guide ambiguity also needs compatibility testing.

Options: (1) four exact PAM seeds (AGG/CGG/GGG/TGG), then extend the guide from the PAM boundary, offer simple wildcard handling and early pruning, but require a complete gap-aware extension and can duplicate states; (2) a unified position-aware bidirectional search allows other search orders and schemes, but wildcard-aware seeding, DP, boundary and coverage proofs are harder; (3) current guide-only search plus a conservative all-overlapping-span precheck is lower risk and preserves candidate semantics but cannot remove discovery/SAM costs. For a first POC use option 1; evaluate option 2 after correctness. A literal `N` in stock Columba, or ordinary edit distance over guide+PAM, does not establish the required wildcard and zero-error PAM semantics.

## CFD during search

Current [CFD code](../src/cfd_score.rs) multiplies guide-position-specific mismatch factors and a two-base PAM factor; it scores reconstructed CIGARs, uses a CRISPRme-compatible DNA-bulge projection, and can return no score. It is a model score, not a calibrated cleavage probability. For ungapped alignments, once a mismatch's oriented guide position and bases are fixed, multiply its factor into a partial product. For nonnegative factors, a safe upper bound is the fixed product times the maximum feasible product of all unresolved factors and PAM factors. If all remaining factors are verified in `[0,1]`, the fixed product times the maximum possible PAM factor is a simple conservative bound; otherwise use explicit per-position maxima including matches, and do not assume unity. Prune only when the upper bound is strictly below a user-selected threshold, accounting conservatively for floating-point rounding and equality. Unknown/missing factors or undefined scores must remain searchable unless the user explicitly chooses a different policy.

Bulges change alignment columns and can change the eventual projection/position assignment, especially when search order changes or DNA-bulge projection removes distal columns. Do not multiply a factor as irrevocably fixed until every permitted completion preserves its identity; otherwise take the maximum over possible projections/remaining states or use an infinite/no-prune bound. Include gap factors and the existing neutral first-position rule exactly where applicable; mixed and unavailable-score cases must match current behavior. State merging must retain the maximum possible score and all eligibility-relevant paths. Verify any bound exhaustively on small cases against completed scores. Threshold pruning is complete only relative to the stated scoring function and threshold, not biologically complete: low-scoring or unscorable sites may still be relevant. Keep CFD filtering optional and off by default; current `-f 0.75` is a match-fraction constraint, **not** a CFD threshold.

## WFA2 and alternatives

| Approach | Correctness / completeness | Runtime and memory | Difficulty / maintenance |
|---|---|---|---|
| A. Current Columba + WFA2 | Existing bounded panels support anchor recovery and row validity; not a universal proof. Candidate discovery uses total edit bound `m + b*z`, separate exact pass and overlap expansion. WFA2 chooses alignments and current reporting chooses representatives; a single optimum is not proof of all eligible paths. | Known e=7 SAM and verification expansion can dominate; index, candidate vectors and SAM cost memory/I/O. | Existing code and validation; lowest change risk. |
| B. Constrained Columba-based search without WFA2 | Can be complete by construction if every allowed anchored path is traversed, correct trace alternatives retained, all output/edge semantics covered, and no unsafe shortcut remains. Not guaranteed by stock Columba. Reproduce WFA scoring/ties or document and approve differences. | PAM-first and separate limits may reduce search and output greatly, but larger multi-label state and repeats may dominate. No measured speedup; bidirectional index remains memory-intensive. | High implementation and proof cost; upstream fork and AGPL maintenance. |
| C. BWA-ALN-derived search | Standard mapper is not complete for this task; a custom exhaustive engine needs new anchored semantics, tracing, output and proof. | Smaller unidirectional index is plausible; seven edits and repeat-heavy branching can be expensive. No comparable benchmark. | High to very high: replace integration, disable/audit heuristics and maintain another fork. |

A direct index traversal can emit full CIGARs or enumerate short matched strings and run a small exhaustive constrained aligner per anchor. The latter removes WFA2 but retains local verification and may be a simpler POC. Neither automatically reproduces current WFA affine scoring, CIGAR trimming, `-f`, gap counting, or representative ties; compare full output records as well as anchor sets. The desired completeness definition must be explicit: all eligible anchors versus all eligible alignments, plus representative behavior. Prove a path exists for each eligible full-guide alignment and that each pruning rule cannot remove it; validate the converse and coordinate conversion independently. Note current implementation's observed outputs may differ from an exhaustive mathematical eligibility oracle.

## Bounded proof of concept (proposed, not run)

1. Record source revisions, index/build flags and binary hashes; use a disposable checkout and small indexes only. Run strict GG, default limits, one thread, with CFD pruning disabled. Preserve the development baseline and frozen artifacts.
2. Reuse the [8 kb real-reference independent panel](real_defaults_validation_49f20fc_2026-11-02_v1/REPORT.md): four CHM13/GRCh38 2 kb windows, 96 designed guides, 204 oracle anchors, including repeats, both strands and 1–2-base bulges. Its oracle independently enumerates each complete PAM and allowed gap placement, not Columba/WFA2. Compare per-guide/contig/strand/exact PAM anchor for recall and precision; audit every CIGAR, counts, match fraction, PAM and CFD independently. Compare representative full records to the baseline separately; investigate differences rather than treating baseline as truth.
3. Add the existing [PAM anchor correction fixtures](pam_anchor_correction_2026-10-30_v1/REPORT.md), including previously missing anchors, and targeted small synthetic cases for all four N bases, both strands, contig ends, reference ambiguity, terminal gaps, alternative eligible alignments and distinct nearby anchors. Exercise other requested PAMs and noncanonical/no-filter modes before claiming compatibility. The default oracle only covers one gap group of length at most two, not every CLI combination.
4. Measure index nodes/intervals, located occurrences, emitted candidates, alignment/trace work, WFA calls, wall/CPU time, peak RSS and temporary bytes, with index construction reported separately. Compare identical inputs and output contract against A and the prior interval-precheck prototype. Report repetitions and any time/memory cap as incompleteness, not an empty result. Require 204/204 anchors, no unexpected anchors, passed independent audit, and explained representative differences before any performance conclusion. Later test broader limits and score-threshold bounds with exhaustive tiny references before considering deployment.

This is a deliberately constructed bounded panel, not a whole-genome sensitivity or speed estimate. No whole-genome experiment, production binary modification, defaults change, frozen-branch change, or CRISPR-Bulge integration was performed for this report.
