# HG00735_pat pilot workflow overhead

2026-11-09. Job **2871278** completed with **21,447** reported PAM anchors; the independent output audit passed every reported record, scored all 21,447 and recovered the known exact target. That audit establishes eligibility of emitted sites, not genome-wide sensitivity. The 758-second CLI workflow contains substantially more than the 82.465-second native search: the current adapter creates a private snapshot, performs **three complete binding verifications inside the CLI**, loads the full reference in native and Python code, and buffers/outputs results. The job wrapper performs **two additional full binding verifications outside the CLI**. None was removed.

Two changes reduce unnecessary work while preserving the existing checks and outputs: the binding checker counts non-ACGT bytes with one equivalent C-level byte pass instead of four counts per FASTA line, and the snapshot runner streams FASTA lines instead of first materializing the entire text and split-line list. They do not alter search, `Search::emit` alignment selection, CFD, the verification comparisons or the production binary. The helper checksum manifest was updated to bind the changed scripts. The prototype continues to copy and check the bundle and to fail on a mismatch.

## Multi-guide reuse and integrity

The integrated `-G` path **already** passes all supplied guides to one snapshot runner and one native process: one snapshot, three internal full checks, one index load and one native reference load per batch. It does not copy once per guide within the batch. On the independent 8 kb/64-guide panel, three current batched runs took **0.428, 0.428 and 0.429 s**; executing the identical 64 guides as separate one-guide invocations took **4.599–4.619 s**. Every run produced the same 172-record PAF multiset and 4,229,884 combined search states. This is a small, warm-cache, same-host experiment; it does not predict whole-assembly batch timing, memory or throughput. Larger batches can increase hit maps and buffered output.

For reuse **across separate invocations**, a persistent verified bundle could avoid copying and repeated hashing only if it is anchored to trusted content and made genuinely immutable throughout all consumers' lifetimes. A suitable design requires a trusted manifest root, atomic publication, kernel/filesystem-enforced immutable storage or a verified read-only namespace, pinned file identity through the entire read, and an API or protected namespace compatible with Columba reopening index paths. `chmod`, timestamps, an unsigned manifest, hardlinks and pre/post checks do not protect against same-user mutation and restoration. Retain full reference N bytes, all component and dictionary bindings, fail-closed checks, and fail-atomic output. No persistent cache, skipped verification or weaker reference/index binding is implemented. Current private snapshots and three checks remain the supported path.

## Validation and limits

The 172-anchor N panel recovered **172/172** and the resolved panel recovered **204/204**, without unexpected or duplicate anchors; their final PAFs were byte-identical to retained pre-change experimental outputs and independent CFD checks passed. The 96 PAM/option comparisons and 11 rejection tests passed, including mismatched reference and altered index. Seven index-checker tests passed. The independent reference-N/boundary fixture recovered 12/12 valid anchors and rejected six invalid PAM cases on both strands, with no extras or duplicates. A deterministic differential test compared the old/new ambiguous-byte formula over 518 strings including all possible byte values, and 3 Mb full-verifier metadata agreed for each alternating run. Streaming/full-text reconstruction produced the same digest on the complete imported reference and matched on wrapped, CRLF, CR, lowercase and duplicate-record fixtures. No production binary was modified.

Recommended next steps are: profile the complete workflow on an authorized future run with separate timers for each check/copy/load/format phase; use bounded batches when outputs and memory are manageable; investigate fewer copies only with a proven immutable reference/index session; and avoid interpreting these proxies as genome-wide performance guarantees. Retain the original backend and all safety checks. The previous pilot's sampled 48 GiB stop was not a hard memory limit, and these optimizations do not change that fact.
