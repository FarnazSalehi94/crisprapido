# Prototype compatibility investigation

The research prototype now supports every two-base A/C/G/T `-p` suffix through a checked entry point, and configurable mismatch, gap and match-fraction bounds within an explicitly limited scope. The existing pipeline and its defaults were not changed. This is **not backend integration**: representative scoring, native index binding enforcement and other compatibility work below remain open.

## PAM and eligibility

`checked_search.py -p XY` searches complete `NXY`, where the first PAM base must be an actual A/C/G/T reference base, and X/Y must match exactly. `-p GG` retains the existing strict NGG rule. Reference N is not a PAM wildcard; all three observed PAM bases must be resolved. Both strands are searched with guide-oriented PAM and CIGAR. The low-level executable keeps its old six arguments for existing research fixtures and accepts optional `PAM MAX_BULGE_EVENTS` as two additional arguments.

The current verifier treats `-m` as the maximum mismatches against resolved guide bases, `-b` as the maximum contiguous gap events, `-z` as the largest event's length, and `-f` as matched guide positions / resolved guide positions, calculated as f32 percent; at least one match is required even for f=0. Adjacent insertion and deletion columns form one contiguous event under this accounting and their lengths add for the z limit. The prototype now reproduces this f32 threshold and event accounting for its **resolved guides**, and exposes m, b, z, f in `checked_search.py`, with defaults 5, 1, 2, 0.75. This implementation supports b=0 or 1 and z=0, 1 or 2; b>1 and z>2 fail explicitly, rather than returning an incomplete subset. Negative limits, malformed or non-finite fractions and invalid PAMs fail. It rejects empty/duplicate guide identifiers, guide N and reference symbols other than A/C/G/T/N before producing records. It does not implement `--allow-noncanonical-pam`, `--no-filter`, multiple gap events, guide N or general IUPAC reference symbols; the checked wrapper rejects unknown CLI flags. These restrictions must be addressed or explicitly surfaced in any later backend.

Prototype rows now expose plus/minus strand, zero-based half-open target coordinates, PAM-adjacent boundary, complete oriented PAM, guide-oriented CIGAR, mismatch count, inserted/deleted bases, gap-event count, match count and match fraction. Per-guide/contig/strand/anchor representative selection remains deterministic; repeated 204-panel runs had byte-identical data rows. It selects by edit count, mismatch count, CIGAR and start, **not** the current WFA score/tie policy: 54/204 representatives on that panel differ in start/end/CIGAR from the current pipeline. They are independently eligible alternatives, but their CFD scores can differ. Neither a score-compatible representative nor full PAF output is provided yet.

## Reference/index integrity

[index_manifest.py](index_manifest.py) builds a fresh index with the specified trusted Columba builder and then creates a binding to the exact reference FASTA bytes and SHA-256 hashes of the vanilla index components used here (`bwt`, `brt`, `rev.brt`, sampled SA and bitvector, text, names, offsets, counts, metadata and header). It checks the reference hash before and after the build and validates names, boundaries and resolved indexed bases. `checked_search.py` verifies the manifest, every component hash, and the reference hash and text/metadata **before** invoking the search. Changed reference bases, including N→A, altered index components, and missing manifests fail without search output. Test coverage is in [test_binding.py](test_binding.py).

Columba substitutes reference Ns, so a pre-existing index alone cannot prove its original N positions. The safe path therefore **requires a manifest generated at the same trusted build**; it rejects legacy unbound indexes and requires rebuilding them for this research entry point. The manifest is an integrity binding, not an authenticated signature; this assumes the builder and binding creation are trusted and the files are not concurrently changed between verification and use. Checks cover the known vanilla/32-bit/sparse-SA-4 component layout. The lower-level C++ research executable can still be invoked directly without the wrapper and does not enforce this binding: that bypass and a stronger native/atomic binding are unresolved integration blockers. Hashing the full index/reference for every invocation is also unbenchmarked at scale.

## Independent validation

[test_options.py](test_options.py) constructs resolved and N-containing targets for all 16 two-base PAM suffixes, all four resolved first PAM bases and both strands. It independently enumerates each PAM-anchored alignment and audits every output's coordinates, CIGAR, mismatch/gap counts and match fraction. **96 option/PAM searches passed**, including m=0/2/5/20, b=0/1, z=0/1/2 and f=.75/0; five unsupported/malformed settings and two invalid guide batches failed clearly. This checks finite examples, not all f32 thresholds or all possible strings.

The checked entry point rebuilt bound indexes for the existing independent panels: **204/204** and **172/172** oracle anchors recovered, no unexpected or duplicate anchors. Both methods recovered 172/172 on the latter. A separate m=0, b=1, z=2 fixture checks two anchors whose only eligible representation is one adjacent I/D event; the prototype reports both and the existing WFA-first path reports neither. The existing fallback enumerates only a single gap direction for equal-length targets, so it does not recover these cases after the WFA optimum fails eligibility. This is a bounded, independently checked difference, not a population-wide estimate. The retained difficult PAM panels recovered **33/33, 3/3 and 4/4**, alternative alignment examples 3/3, both-strand N/PAM boundary cases passed, resolved/random-N sets were 29/29 and 17/17, all four N substitution indexes yielded 40/40 prototype anchors, and all 64 triple-N replacement tests passed 8/8. These were rerun after the compatibility change. The 2 Mb runs in the prior report were not rerun for this change and are not exhaustive oracles. The results are finite tests and do not prove genome-wide completeness.

## CFD compatibility

The existing scorer takes the original guide, target **in guide orientation**, guide-oriented CIGAR, and the observed oriented PAM's final two bases. [cfd_probe.rs](cfd_probe.rs) invokes the actual `crisprapido::cfd_score::get_cfd_score`; [test_cfd.py](test_cfd.py) independently reconstructs alignments from prototype rows and compares it with the separate matrix calculation in `scripts/release_validation/audit_emitted.py`. Across 1,024 prototype rows covering all 16 PAMs, both strands and `=`, `X`, `I`, `D`, all scores agreed: 896 scored and 128 returned no score. Both mixed I/D fixture alignments also agreed as unscorable (`None`). The original 204 panel scored 204/204; the 172 panel scored 97 and returned no score for 75 N-containing rows. An unavailable score remains `None`, not zero. No CFD pruning or production output integration was added. The test checks the chosen prototype alignment; it does not resolve the 54 representative differences or establish equal scores for different valid alignments.

## Why the old pipeline missed sites

The previous synthetic substitution cases had 2–3 baseline misses for each of four N substitutions despite independently eligible anchors. The original e=7/e=0 Columba SAMs had no candidate anywhere on each missing guide/contig, although the substituted target has an independently calculated one-gap edit distance 6 or 7. The issue was isolated further:

1. With substitute A, rebuilding each of the three missing short contigs **alone** produced an e=7 candidate and the unchanged CRISPRapido verifier recovered the anchor. The isolated index's N replacement was verified as A, matching the multi-contig experiment.
2. In a disposable Columba 2.0.3 build, changing only the nearby-occurrence check in `IndexInterface::getUniqueTextOccurrences` as shown in [columba_probe.patch](columba_probe.patch) restored a mapped candidate on every originally missing guide/contig for A/C/G/T. Running the unchanged Columba + WFA2 verifier with that diagnostic binary recovered **40/40** oracle anchors for all four index substitutions, no extras or duplicates. Experimental SAMs and comparisons are retained in [results](results/).
3. The source performs redundancy suppression on concatenated absolute start positions with `maxDiff = 2 * maxED` **before** sequence assignment (`findSeqName`); it does not key this check by contig. The diagnostic intervention establishes that this suppression causes the missing reported candidates in these fixtures. The isolation result and source ordering support cross-contig proximity as the mechanism; individual discarded predecessor relationships were not traced, so this is not a proof of exactly which record suppressed each hit or of genome-wide prevalence.

The diagnostic binary and patched library were built in `/tmp`; no production binary or external Columba checkout was modified. The patch removes a redundancy filter globally and is **not** proposed as a production fix: its performance and other correctness consequences are untested. This is a candidate-generation/output issue before WFA2, rather than evidence that the independent oracle was wrong.

## Reproduction and remaining work

Use `index_manifest.py build --builder BUILDER --reference REF --index NEW_PREFIX`, then `checked_search.py --poc POC_WRAPPER -r REF -G GUIDES --index NEW_PREFIX -p GG -m 5 -b 1 -z 2 -f .75`. `test_options.py`, `test_binding.py`, the prior panel scripts and `test_cfd.py` are standalone bounded checks; build the latter with `build_cfd_probe.sh` using a separately built repository `.rlib` and dependency directory. The diagnostic Columba patch is scoped to a disposable source copy and must not be used as a production fix.

Before proposing experimental integration: enforce reference/index identity inside the actual backend with appropriate concurrent-update guarantees; support or explicitly gate the remaining CLI modes and larger gap configurations; define score/representative compatibility and downstream CFD/PAF behavior; test source/index version and 64-bit modes, wider parameters, repeat-heavy and N-heavy inputs, boundaries and randomized alignments; independently review the Columba suppression issue and a safe per-contig candidate policy. No production binary/default, frozen branch or main was changed; no genome-scale experiment, CFD pruning or CRISPR-Bulge integration was performed.
