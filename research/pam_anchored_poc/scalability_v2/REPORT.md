# Experimental PAM-aware backend: index audit and bounded scaling

2026-11-05. **The 3 Mb runs were supported and completed under the chosen limits, but chromosome- and whole-genome-scale safety remains unproven.** A small code change replaces repeated FASTA record concatenation with chunk accumulation in the binding checker and snapshot runner; it does not remove hashes, index/reference comparison, snapshot copying, native verification or post-search verification. On a 2 Mb reference, five alternating same-input full binding checks fell from **0.890–0.900 s to 0.258–0.263 s**. Both independent 204- and 172-anchor panels still pass with byte-identical experimental PAFs. The 3 Mb outputs agree across backends and pass independent replay, but were not exhaustively enumerated.

The full source and integer analysis is in [INDEX_AUDIT.md](INDEX_AUDIT.md). The relevant bound is `uint32_t` text positions: after the required terminal symbol, ordinary 32-bit input can theoretically contain at most **4,294,967,294 reference bases total**, including all contigs. This is a representation limit, not a guarantee that an input near it works. Above 2,147,483,647 indexed symbols, the 32-bit builder switches to a temporary 64-bit suffix array; the two simultaneously live SA arrays alone can need about 12 bytes per symbol. Real builder and search memory is higher. A chromosome-sized index is numerically within the format limit but has not been tested or shown affordable. A complete human reference might fit depending on composition, but neither the memory requirements nor boundary correctness of that case are established.

## Safe overhead reduction

[The checker](../validation/index_check.py) now collects wrapped record lines and joins each record once instead of repeatedly appending to an immutable string. [The snapshot runner](../integration/run_snapshot.py) does the same when reconstructing the reference for target extraction. No search, representative-selection or CFD logic changed. Full reference and component hashes, resolved-base/index-text checks, contig metadata checks, private copies, mandatory native check and final snapshot check remain in place. Existing binding tests rejected changed reference N, modified index components, missing manifests and PATH verifier substitution; 96 integrated PAM/option comparisons and 11 rejection checks passed. Six index-checker unit tests, including new wrapped FASTA and duplicate/empty record regressions, passed.

[compare_verifier.py](compare_verifier.py) alternated five old-checker and five new-checker full `index_manifest.verify` calls on the exact same prebuilt bound 2 Mb reference, checked their independent metadata results were equal, and retained all results in [verify-comparison.json](results/verify-comparison.json). Median elapsed fell from **0.897 s** to **0.259 s** on this host. This is a full-verification comparison with warm OS caches, not a separately timed hashing speedup. For the integrated 2 Mb workflow, three new runs were **1.725–1.752 s**, with byte-identical PAF to the prior three **4.50–4.76 s** runs. These end-to-end runs occurred on different dates and are an indicative historical comparison, not a controlled paired speedup; see [2mb-after.json](results/2mb-after.json) and the [prior measurements](../scalability/REPORT.md).

The remaining overhead is material: every run still copies the full bound reference/index and verifies three times; checker and runner still materialize full records and additional text copies, the native executable loads FASTA plus FM index and retains anchor representatives, and Python/Rust buffer output. Index constructor time was about 3 ms at 2 Mb in the earlier instrumented warm-cache measurement; it is not evidence for cold storage or large references. Search-state count is not search-state *memory*: DFS depth is guide-length bounded but each path stores strings, SA interval expansion and output maps can grow with repeats and reported anchors. The list-of-chunks change improves elapsed time but still uses O(reference size) memory and is not a chromosome-scale streaming implementation.

A reusable immutable bundle is promising but **not implemented**: filesystem `chmod 0400`, path names and an unsigned JSON manifest alone do not prevent a same-user writer replacing or mutating files between verification and use. A sound design needs an authenticated content manifest; atomic creation/publish of all index components and the exact original FASTA; a trusted immutable snapshot or read-only mount with a protected namespace and content-verifying filesystem (or equivalently pinned file descriptors and verified immutable storage); and a consumer that can open exactly those pinned objects. Cache verification only while the immutability guarantee remains enforced. Keep fail-closed behavior on missing verification, replaced objects or untrusted storage, and verify an output spool before publishing results. No unchecked cache, verification bypass or weakened binding has been introduced. The current trusted-input/same-user adversary limitation remains.

## Multiple guides and independent correctness

The independent 172-anchor panel contains eight 1 kb CHM13/GRCh38 reference-derived and deliberately N-edited windows, including repeat-enriched candidate extracts. Its **64 guides** span GC fractions **0.20–0.55**, **7–14 distinct dinucleotides**, and **1–6** reported anchors per guide. Both current workflows recovered **172/172**, with zero missing, unexpected or duplicate anchors; all 172 emitted alignments were independently replayed and all 97 defined CFD values independently agreed. **75 emitted target spans overlap reference N**, 33 plus and 42 minus; these Ns are engineered, not naturally observed positions. The current baseline output and experimental output each matched their prior retained outputs byte-for-byte. Per-guide characteristics are in [172-guide-characteristics.json](results/172-guide-characteristics.json).

The independent synthetic N-substitution panel adds a low-complexity `AC` repeat guide (two distinct dinucleotides) and a more complex guide (12), plus N-overlapping targets, mismatch+1/2-base bulges, consecutive Ns and both strands. Across four controlled substitutions of indexed N with A/C/G/T, the **integrated experimental backend recovered 40/40 oracle anchors each time**, zero extras/duplicates; all 40 emitted spans overlap N and their CFD scores are unavailable under the existing scorer. The baseline recovered **37, 38, 37, 37**, respectively; its 2–3 missed anchors were absent from both e=7 and e=0 Columba candidate SAMs on the corresponding contigs. This repeats an established short-multicontig candidate-generation discrepancy; its exact Columba mechanism and genomic frequency remain unresolved. We do not treat baseline disagreement as proof of experimental error. See [integrated](results/n_substitution/integrated.json), [baseline/native](results/n_substitution/native-and-baseline.json) and the [independent panel generator](../readiness/substitution_oracle.py). This small constructed panel is not a representative genomic benchmark.

On the 172 panel the backends selected different eligible representative alignments at **61/172** anchors, with **22** independently calculated CFD differences; N-containing scores can be unavailable. No alignment was selected by CFD. [Detailed independent comparisons](results/172-alignment-comparison.json) retain the alternatives. The 3 Mb cases below had three different representatives each; CFD differed at two CHM13 and three GRCh38 anchors. Different eligible CIGARs are not treated as errors, and CFD is not a calibrated cleavage probability.

## Controlled 3 Mb experiment

Source arithmetic and file format were audited before proceeding. [prepare_3mb.py](prepare_3mb.py) extracted only CHM13 chr1:100000001–103000000 and GRCh38 chr9:34000001–37000000 from indexed FASTA, then built and bound new 3 Mb indexes. Both windows contain no Ns. The GRCh38 window extends the prior repeat-candidate region; this is a candidate label, not a repeat annotation of every base. Both used the same ELMOD2 guide and default m5/b1/z2/f0.75/NGG. Preparation used a 180 s build limit and 2 GiB per-process virtual-memory cap; each build plus binding took **0.77 s**. A separate full reference/index verification took **0.47 s** CHM13 and **0.42 s** GRCh38. These single preparation timings include local cache effects, do not measure builder peak memory, and are separate from search.

Each workflow had one thread, a 90 s wall cap, a 2 GiB per-process virtual-memory cap, and a sampled aggregate RSS stop at 1.5 GiB. [benchmark_tree.py](benchmark_tree.py) samples the process group every 0.1 s, sums RSS, and kills the group if the sampled limit is crossed. Summed RSS can double-count shared pages and polling can miss transient peaks: these are approximate sampled process-group peaks, not exact physical-memory high-water marks. A state-count cap cannot interrupt the current native code before completion; the wall and sampled-memory caps are the enforced stop mechanisms. One run per case was performed; no extrapolation or robust speed ratio follows.

Both complete workflows include input, output and downstream CFD; the original also includes Columba SAM processing and WFA2; the experimental includes snapshot copying and all checks. Index preparation is excluded. The experimental native timer includes traversal and locate/replay but excludes loading, binding and scoring, and is not equivalent to baseline candidate-generation time. Both reported **20/20 shared** CHM13 and **18/18 shared** GRCh38 anchors, zero backend-only or duplicates. [Independent audits](results/3mb/) replayed every alignment, checked eligibility, strand and PAM, and independently recomputed CFD. These are emitted-site checks, not an independent exhaustive 3 Mb recall oracle, and the same guide was used in both regions. Search states grew relative to the earlier 2 Mb runs, but neither limit was approached; selected windows and one guide do not characterize extreme repeats or high-output workloads.

## Recommendation and reproduction

Continue experimental bounded evaluation. Before a whole-genome pilot: obtain a reproducible trusted Columba source/build and format contract; implement and validate 64-bit or PAM-aware sharded indexes and boundary arithmetic where needed; replace repeated whole-input copying, verification and buffering with a genuinely immutable verified bundle and fail-atomic streamed/spooled output; characterize aggregate memory and state explosion for repetitive, N-heavy, many-guide and high-output cases; broaden independent oracles and N-overlap testing on genuine reference windows; and decide how representative alignments and downstream CFD differences are communicated. The current unsigned manifest and trusted snapshot model do not resist a malicious same-user writer; protect that threat boundary explicitly before treating a reusable bundle as immutable.

The 3 Mb experiment is reproducible with [prepare_3mb.py](prepare_3mb.py), [benchmark_tree.py](benchmark_tree.py), and the prior independent [audit.py](../scalability/audit.py). Their inputs, bounds, FASTA hashes and manifest hashes are recorded in [results/3mb](results/3mb/); no large genomic FASTA or index is committed. [check_substitutions.py](check_substitutions.py) runs the integrated path on the separately generated exhaustive N panel. All measurements used the same host and one search thread, with caches and other shared-host activity uncontrolled. Original backend/defaults, production binaries and frozen branches were not changed; no whole-genome search, CFD-guided pruning or CRISPR-Bulge integration was performed.
