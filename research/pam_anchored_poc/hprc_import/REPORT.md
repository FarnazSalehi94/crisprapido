# Importing an existing HPRC Columba index

The importer [import_index.py](../compatibility/import_index.py) stages an existing 32-bit vanilla index without constructing a BWT or suffix array. It uses a caller-supplied trusted assembly manifest, complete component-hash manifest and checksum-pinned independent comparator. The caller selects the compressed FASTA via its assembly row; source paths and their expected hashes are taken from the supplied evidence. The exact source FASTA path is selected from the assembly manifest; the input is the original compressed FASTA. These inputs are a trust boundary: an untrusted or incorrectly pinned manifest/comparator cannot establish biological identity by itself. The importer does not infer trust from matching filenames, contig metadata or an index alone.

## Protocol and safety

The importer creates a **new exclusive private directory**, writes `.incomplete`, and never writes to the source files. It copies and SHA256-checks the compressed FASTA against the trusted assembly manifest; fully decompresses it into the exact byte-preserving plain FASTA used for replay; checks the trusted `.fai` digest; and copies and hashes every one of the 12 index components against the corresponding trusted component hash. It checks tag/width/flavor, single-file marker, contig names, order and lengths against `.fai`, `.sna`, `.headerSN.bin` and `.pos`, and rejects duplicate/empty identifiers and symbols unsupported by the experimental search. A checksum-pinned comparator independently streams the staged gzip against the staged `.txt.bin`, reproducing the verified Columba `minstd_rand(42)` N-replacement rule. It checks complete content, sentinel, length and record count. This assumes the trusted builder-normalization provenance applies to the supplied index; it does not prove that a SHA-pinned FM data structure is algorithmically correct.

After the verifier was strengthened to compare its streamed FASTA hash, the actual HG00735_pat stage was reverified successfully with all 12 components; the additional pass took 166.95 s and 15,372 KiB maximum individual-process RSS ([evidence](results/final-reverification.json)).

The original N-containing reference is preserved, rather than reconstructed from Columba's substituted indexed text. The bundle's reference SHA256 binds the **exact decompressed bytes**. It is an exact match to the decompression of the compressed file that matched the supplied trusted SHA256; it is not an independent claim about a biological assembly outside that trust chain. All 12 component hashes and their trusted manifest are part of the same claim. The importer writes the candidate binding in a private verification namespace, runs the normal `index_manifest.verify` against all staged components and reference, then atomically publishes the consumer-visible sidecar only after all checks succeed. Failed imports do not publish a binding; `.incomplete` and partial files remain for diagnosis and should not be consumed. On success the staged files are made read-only, but ordinary file mode does not stop a malicious same-user writer; the existing runtime's repeated snapshot and validation and its documented same-user race limitation remain.

To keep verification practical on long inputs, [index_check.py](../validation/index_check.py) now checks FASTA versus `.txt.bin` by streaming, accumulating only contig names and lengths rather than full copies. It still hashes the exact reference and index components and checks resolved bases and metadata; the verifier now also compares the FASTA hash calculated during the streaming check with the binding, detecting a change between its first digest and that read. A simulated mid-verification reference change was rejected. For Ns its text comparison intentionally permits the indexed replacement. Full N identity comes from the pinned source hash and separate normalization comparator. The checker still reads one FASTA line at a time, so unusually long unwrapped lines can require large line buffers; this is not a general constant-memory guarantee. The native search's later mandatory binding check and the checked adapter are not bypassed.

## Remaining barriers

A successful import does not prove large-coordinate `findSA` correctness, both-strand PAM anchors, sensitivity, or safe memory use for a whole-assembly query. The index uses 32-bit unsigned positions and the indexed assembly is above 2^31 but below 2^32; billion-scale suffix-array locate, contig transitions, both strands, reference Ns and the plus/minus PAM boundary conversions need independent targeted validation. The experimental backend currently searches the entire index for every guide and only evaluates reference coordinates after locating occurrences. Filtering results by genomic interval at emission would **not** restrict FM-index traversal or the work of enumerating the relevant global SA intervals.

Genuine indexed region restriction would require a mechanism to test and report the intersection of each SA interval with the genomic-position range during traversal/locating, such as a validated positional range-reporting structure over SA values; this has construction, storage and correctness costs. Alternatively, an independent bounded-reference search can be used for validation, but that is not reuse of the original whole-assembly FM index. No such mechanism or genome partitioning was implemented.

The importer stages one full copy of the index and a plain reference. The existing experimental adapter then copies that complete bundle into a private snapshot for every run and performs multiple full verification passes; its Python runner and Rust adapter also buffer output and reconstruct reference data. A verified import therefore enables the current binding interface but does not establish scalable repeated use. A future immutable verified bundle, streaming/spooled output and a fail-atomic reuse contract need independent design; do not weaken mandatory reference/index identity to avoid those copies. The manifest is unsigned and the stage is not adversary-proof against the same user.

A separate native load-only probe completed against the imported index **without accepting or searching a guide**. It first ran the mandatory binding verifier, then constructed the same `FMIndex` configuration as the prototype and exited. The index constructor took **4.11 s** in this warm-cache run; the complete process including its verification took **170.09 s**. GNU time measured **11,190,868 KiB (10.67 GiB) maximum individual-process RSS**, under a 24 GiB per-process virtual-address limit and 600 s wall cap. The constructor reported **3,029,527,753 indexed symbols**, including the terminal sentinel. This proves that this build loaded this staged index and represented its length; it does not exercise guide search or guarantee that every lazily mapped suffix-array page was resident. It excludes the actual prototype's separately loaded reference, locating/traceback, hit maps, output and runner memory, so it is not a whole-backend peak. See [load-only measurements](results/load-only.json).

An additional read-only [serialized-offset sample](results/large-offset-sample.json) inspected the first 1,024 32-bit SA entries: 258 fell above 2^31 inside a contig. For example global offset 2,410,907,752 mapped by the recorded `.pos` dictionary to `HG00735#1#JAHBCH020000046.1` offset 40,274,126. This checks unsigned decoding and arithmetic on a small raw sample only; it does **not** call `findSA`, establish reference bases at those positions, or prove search-coordinate correctness. [inspect_large_offsets.py](inspect_large_offsets.py) reproduces the sample without a search.

## Reproduction and tests

The importer is invoked with `--assembly`, `--assemblies`, `--components`, `--comparator`, `--comparator-sha256` and an output directory that must not yet exist. It reads the selected compressed FASTA and original prefix from the trusted assembly manifest. The completed stage above can be reused; rerunning the following would create another full copy:

```bash
python3 research/pam_anchored_poc/compatibility/import_index.py \
  --assembly HG00735_pat \
  --assemblies docs/index_recovery_2026-10-29_v1/verified_assemblies.tsv \
  --components docs/index_recovery_2026-10-29_v1/verified_component_checksums.tsv \
  --comparator /export/local/home/salehi/crisprapido-index-recovery-v1-2026-10-28/tools/compare_index_text \
  --comparator-sha256 2306463cb7a94f1da01842b554be4c1e5da83542a3d6905b6b698239ee54f89a \
  --out /path/to/new-exclusive-stage
```
 [test_import_index.py](../compatibility/test_import_index.py) uses an existing small index and checks a successful import, wrong reference, corrupted component, wrong source digest and subsequent mutation of a published staged reference/component. [test_staged_rejection.py](test_staged_rejection.py) tests a published large bundle using separate fake paths and never modifies it. Seven index-checker tests, a mid-verification mutation test and the independent 172-anchor panel test cover the streaming checker and existing backend behavior.

A separate [load-only probe builder](build_load_probe.py) uses the prototype's `FMIndex` constructor and mandatory native binding check, then returns without taking or searching a guide. Its results must not be confused with full-backend search memory or overall sensitivity. Source paths, component hashes and audit logs are recorded as small artifacts; the staged reference and index stay outside Git. The original index, production binaries, defaults and frozen branches were not modified, no index was rebuilt, and no whole-assembly guide search was launched.
