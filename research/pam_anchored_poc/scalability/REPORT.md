# Integrated PAM-aware backend: bounded scaling study

2026-11-04. On the tested 100 kb–2 Mb windows, the experimental backend recovered every locus reported by the existing backend and passed independent alignment and CFD replay. For the three 100 kb windows, an independent exhaustive oracle also agreed with both backends, including two sites in the natural-N window. There were no backend-only or duplicate anchors. These results support continued bounded evaluation; they do **not** establish complete 1–2 Mb recall, whole-genome correctness, or safety at that scale. A controlled whole-genome pilot is **not yet justified**: the 32-bit research index and snapshot/check implementation have not been validated at that size; the full-file verification and buffering costs, process-tree memory, repeat-heavy worst cases and representative/CFD policy need work first.

The experimental end-to-end runs were faster on every measured pair here, using the same settings, reference, guides, reporter, host and one thread. This is an empirical comparison of these workloads, not an isolated FM-index speedup or a forecast for other guides. Both methods report one eligible representative per anchor, but can select different representations and thus different CFD values.

## Regions, guides and methods

[regions.json](results/regions.json) records each exact header, source, source and extracted FASTA hashes, guide, N count and index size. CHM13 uses the nested **prefixes** of the existing chr1:100000001–102000000 ordinary-candidate reference; GRCh38 uses nested prefixes of chr9:34000001–36000000, a previously selected repeat candidate. They are 100,000, 1,000,000 and 2,000,000 bases, with prefix offset zero relative to the parent. The prior report described the GRCh38 benchmark as chr9:30000001–32000000, but the actual input header and retained [window metadata](../../../docs/release_validation_0aa9944_2026-11-02_v1/scaling/windows.json) are **chr9:34000001–36000000**; the latter identifies this study's source. Both parents contain only A/C/G/T. All six scaling cases use the ELMOD2 guide `TCTAGCGTTTAACTTCTTCG`.

A separate native GRCh38 chr1:1–100000 extraction contains 10,000 Ns at the initial assembly gap. Its guide `AACCCTAACCCTAACCCTCG` has a strict NGG at local PAM start 10470, 470 bases after the N run. This is not the scaling guide. Both reported targets are resolved and neither overlaps an N. Consequently it tests carrying a natural N run in the indexed region, not recall of N-overlapping target alignments. The earlier engineered-N exhaustive panels remain important complementary evidence.

The GRCh38 scaling parent was selected using a prior repeat proxy, not annotated repeat boundaries. To characterize the actual prefixes, [characterize.py](characterize.py) samples 100 equally spaced resolved 20-mers and checks for a second nonoverlapping occurrence in the same window. The repeat-candidate prefixes yielded 16/100, 14/100 and 14/100 repeats at 100 kb, 1 Mb and 2 Mb; the CHM13 prefixes yielded 2/100, 7/100 and 8/100. This coarse within-window proxy does not establish repeat class or general repetitiveness. Each window contains many nearby strict PAMs: for example the 100 kb GRCh38 repeat candidate has 2,154 plus and 2,052 minus consecutive same-strand PAM pairs separated by at most three bases. Counts for all windows are in [characteristics.json](results/characteristics.json); nearby PAMs do not imply eligible off-targets for the chosen guide.

All 42 timed workflows completed: three alternating sequential runs per backend for each of seven cases, `-m 5 -b 1 -z 2 -f 0.75 -p GG -t 1`. The existing path was selected explicitly; the experimental path used the integrated adapter and separately built native binary. Every reference/index pair was freshly built and bound **before** timing; the experimental path did its mandatory copy and checks each run. The earlier prebuilt indexes lacked the mandatory reference binding, so these scratch indexes were rebuilt with bound manifests. Index construction is excluded from all times. Both end-to-end times include FASTA input, search, verification, CFD and PAF writing. The existing path includes Columba's SAM generation, SAM parsing and WFA2; the experimental path has no SAM or WFA2 but includes snapshot copying and three binding verifications. CFD is downstream for both. The host was `octopus01`, AMD EPYC 7402P; binaries and hashes are in [provenance.json](results/provenance.json). Existing Columba source-to-binary provenance remains qualified as in the [prior report](../validation/REPORT.md).

Each workflow had a 90-second wall limit and `ulimit -v 2097152` (2 GiB virtual address space **per process**, not a process-tree total). No case hit the limit. GNU time's reported maximum RSS is the maximum of an individual process, **not simultaneous aggregate memory of all subprocesses**. Execution was on the same shared host; caches and other host activity were not controlled. The very first CHM13 100 kb baseline run took 3.91 s versus 1.53 s subsequently, so cold/warm effects are visible. No whole-genome input or whole-genome experiment was run.

## Results and correctness

The independent [audit.py](audit.py) extracts targets and PAMs directly from FASTA, replays every PAF CIGAR, checks reference and guide consumption, strand, coordinates, mismatch and contiguous-gap counts, 15/20 match minimum and strict NGG, and recomputes CFD with the independent score-matrix implementation. A separate direct-string oracle enumerates both strands, every strict PAM, every gap placement and every contiguous gap event up to two bases, including adjacent I/D. It uses true reference Ns as mismatches in aligned columns. [test_oracle.py](test_oracle.py) agrees with 14 expected sites for six selected guides from the existing independent 172-anchor panel, including mismatch/bulge cases on both strands. The three complete 100 kb oracle enumerations agree with both outputs. The 1–2 Mb cases have independently audited **emitted sites** and cross-backend agreement, but no exhaustive whole-window oracle; either backend could theoretically miss the same locus.

The duplicate column is original / experimental. The windows are nested, so rows are not independent and their sites should not be summed. Both empty 100 kb cases are useful negative tests, not positive recall evidence. All outputs were byte-identical across each backend's three repetitions. For the native-N window's minus anchor 18095, for example, the two eligible 5-mismatch, 2D alignments give CFD approximately 0.00011646 and 0.00155280. This results from different valid gap placements, not a missing site or evidence of a preferred biological alignment. CFD is not a calibrated cleavage probability. The backend continues to use its deterministic edit-count/CIGAR selection, not CFD maximization.

For the original CHM13 2 Mb case, a separate run retained the two Columba SAM files and reproduced the measured PAF exactly. Its two mapping-worker elapsed values summed to **0.289 s**, SAM files totaled **1,578,046 bytes**, and total workflow time was **29.73 s**. Worker time includes Columba's own mapping/reporting and is not equivalent to the experimental search timer; SAM writing, loading, WFA verification and other work cannot be separately derived from that number. See [baseline_phase.json](results/baseline_phase.json). Earlier instrumented bounded runs identified WFA verification as substantial work, but the present study does not isolate every original phase or aggregate process-tree memory.

In the nested size series, experimental state counts rose about 10.7× (CHM13) and 12.8× (GRCh38) from 100 kb to 2 Mb, a 20× size increase; that is not a scaling law. GRCh38's repeat-candidate series had more states than CHM13's for this guide at each size. At 2 Mb, experimental end-to-end time grew about 2.5× from 1 Mb despite only about 1.4–1.7× as many search states; repeated full-file checking is a material contributor. These data do not test highly repetitive centromeres, many guides, larger indel limits or genome-scale site output.

## Snapshot, verification and index loading

[profile.py](profile.py) separately repeats snapshot copying, the same binding verifier, native search, and re-verification. Its native executable is a separately compiled copy with a timer around the Columba `FMIndex` constructor ([build script](build_index_timer.py)); its CHM13 1 Mb native rows were checked byte-for-byte against the original native prototype, and its state counts matched the integrated benchmark in all seven regions. The numbers are not subtracted from a particular end-to-end benchmark run and include host/cache noise. For 2 Mb, median snapshot copies took **0.007–0.010 s**, each standalone full verification **0.87–0.92 s**, and the native constructor **0.0030–0.0031 s**. Native process time outside its traversal timer was **0.96–0.98 s**, including its own mandatory verification, FASTA parsing, process startup, index loading and output; it is not pure load time. At 1 Mb, each standalone verification took about 0.29–0.33 s and constructor about 0.0014–0.0019 s; 100 kb checks took about 0.015–0.018 s. Copying totals approximately 7.6 MB of index components plus 2 MB reference for each 2 Mb run. See [profile.json](results/profile.json) for individual repetitions.

The check hashes the bound files and independently reconstructs and compares indexed text with the FASTA. [index_check.py](../validation/index_check.py) also accumulates each FASTA record by repeated string concatenation. The observed verification growth, repeated three times per integrated search, is a bottleneck and is not evidence that a whole-genome check will scale linearly. Temporary full copies, buffered stdout and reference parsing also constrain memory and disk at larger sizes. These safeguards should not be bypassed; scalable, immutable binding and streaming output need development.

## Controlled N ablation

[n_ablation.py](n_ablation.py) replaces each of the 10,000 reference Ns with the actual indexed A/C/G/T substitution from that specific bound index, then builds a new index on this **synthetic** shadow FASTA. All 12 index components were byte-identical to the natural-N index ([hash comparison](results/n_ablation/index_component_equality.json)); the references and manifests remain distinct. Three repeated complete workflows used the same guide and limits. Natural versus shadow experimental runs both explored **1,411,449 states**, reported the same two PAF rows, and took 0.22/0.22/0.22 s versus 0.22/0.22/0.27 s; traversal was 0.111/0.111/0.111 versus 0.111/0.110/0.140 s. Original backend PAFs were also identical and took 0.62/0.62/0.62 versus 0.61/0.61/0.67 s. Both references' two anchors were independently enumerated. See [ablation runs](results/n_ablation/runs.json) and [summary](results/n_ablation/summary.json).

This controlled case indicates no detectable N-related penalty beyond run variability when the FM text is identical and reported targets do not contain Ns. It cannot characterize replay cost or recall when many eligible sites actually overlap Ns, or how a different indexer's substitutions change search states.

## Reproduction and next steps

[prepare.py](prepare.py) accepts the prior bounded-reference directory, indexed GRCh38 BGZF, samtools, trusted Columba builder and scratch output path; it creates small windows and freshly bound indexes. [benchmark.py](benchmark.py) runs both selected backends under the listed caps, [summarize.py](summarize.py) checks repeat hashes and calls the independent auditor, and the remaining scripts reproduce N ablation, repeat proxies and timing breakdowns. Paths for the original source and all derived sequence hashes are retained, but genomic sequences and indexes are not committed. Bound manifests are retained only as small verification/provenance records. The actual runtime binary, prototype, builder and host-specific loader paths must be supplied locally. Keep phase instrumentation separate from the repeated end-to-end runs.

Before a pilot, validate larger but still bounded and more diverse real regions and guides, including N-overlapping eligible sites, extreme repeats, dense outputs and boundaries; establish source/build reproducibility and 64-bit/index-format constraints; profile aggregate memory and failure/timeout behavior; replace the current full-copy and repeated verification design with a scalable checked immutable-input contract; and agree how alternative alignments affect reported CFD. These are prerequisites to reconsidering a controlled whole-genome pilot, not authorization to run one.
